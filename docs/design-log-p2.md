## Growth factor and amortized cost
For the Conversation class, I implemented a dynamic array with a growth factor of 2. Appending to an array at full capacity, where size_ == capacity_, a new array of twice the size is allocated, and the existing elements are then able to be copied over before the element is appended.
I can prove this yields an amortized insertion cost of O(1). The cost of inserting an element is the cost of the actual insertion (1) plus the cost of copying existing elements for each resize triggered, which happens at capacities 1, 2, 4, 8, etc.
To insert N elements, the program performs N basic insertions and N- 1 copy operations. The formula for the total operation cost is 2N - 1, which is bounded by O(N). Dividing the O(N) total cost by the N insertions yields an amortized time complexity of O(1) per append operation. 

## Rule of Five evidence
Because Conversation is forbidden from using std::vector, it directly manages a raw heap-allocated array of Message objects. To prevent memory leaks, double-frees, and dangling pointers, I implemented the complete Rule of Five. 
      The destructor simply calls delete[] data_, ensuring any dynamically allocated memory is returned to the system when the conversation goes out of scope. The copy constructor and copy assignment perform deep copies. Instead of copying the pointer the program allocates a brand new Message array matching the capacity of the source. I then iterate through the source elements and copy their contents into the new buffer. The move constructor and the move assignment optimize performance by taking the memory pointer from a temporary source object. After taking ownership of other.data_, the program immediately makes the source object's members zero, so other.data_ = nullptr, other.size_ = 0, and other.capacity_ = 0. This ensures the moved-from object remains in a valid, empty state and its destructor will safely call delete[] nullptr without crashing. 

## Sentinel scanner: bounded pending_ proof
The SentinelScanner is designed to detect a multi-character sentinel string (length L) within a stream of arbitrarily chunked text without concatenating the entire stream into memory. 
To guarantee O(1) spatial complexity per chunk, the scanner's pending_ buffer holds a maximum of L - 1 characters at any time. The mathematical guarantee works as follows: 
Let L be sentinel_.size().
       Before any feed operation, pending_.size() L – 1. Then a chunk of size C arrives. The new concatenated string length is S = pending_ + C . Then the program searches the string S for the sentinel. If the sentinel is found, we flush the buffer up to the sentinel, and pending_ becomes empty (L – 1). If the sentinel is not found, we cannot rule out that the final characters of S might form the beginning of a sentinel with the next chunk. The maximum possible partial match that could overlap with the next chunk is exactly L - 1 characters. Finally, the algorithm safely emits S - (L – 1) characters and retains only the trailing L - 1 characters in pending_. Therefore, at the end of the execution block, the size of pending_ is reset to L – 1. As pending_ never exceeds L - 1, the memory amount concerned relies solely on the length of the sentinel, avoiding a possible memory leak caused by unbounded string concatenation. 

## What I would change differently
For starters, I would start the project earlier! I would also plan more so that I can keep track of what the status is on the project at any given time. But concerning the code itself, if I were to rewrite this project, I would probably change the initialization strategy in the Conversation class. Currently, the default constructor initializes capacity_ to 0 and data_ to nullptr. While this is fine for completely empty conversations, it guarantees an immediate reallocation on the first append operation.
Pre-allocating a small default capacity, such as 4 or 8, in the default constructor would be marginally better. Paying a tiny, fixed memory cost upfront would eliminate the overhead of the initial 0-to-1 and 1-to-2 capacity jumps.
